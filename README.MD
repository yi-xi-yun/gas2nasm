# gas2nasm

Copyright(C) 2004 H.Kawai, 2026 yi_xi_yun.

gas2nasm是一个将GCC生成的32位GAS汇编转换为**可被nasm直接编译**的.asm汇编的转换工具，主要针对那些需要以nasm代替gcc工具链进行编译、链接的场景而开发。

## 背景

相比市面上大多数AT&T转为Intel汇编的工具主要解决指令上的语法差异，本工具的设计目标在于生成“可直接交给nasm编译”的文件。GCC的.s文件中充斥着大量对段声明、对齐、调试信息、符号可见性、字符串常量等面向编译器的伪指令，如果不对这些指令进行良好的支持，便无法让输出的文件被nasm所编译。

本工具面向Windows下MinGW环境，专用于处理MinGW-GCC生成的.s文件，生成的结果可直接由`nasm -f win32`或`nasm -f bin`的指令进行编译。

本工具派生自 H.Kawai（川合秀实）为《30天自制操作系统》配套开发的gas2nask，原程序的目标是把gcc输出转换为其自制nask汇编器的语法。

笔者的改造原因主要集中于：（一）将其输出的目标由nask改为标准的nasm文件；（二）原程序年代较早，对现代gcc编译器输出结果的支持有限。本工具针对现代MinGW-GCC的输出特性与nasm汇编器的语法规则做了适配可用于更多的gas汇编--nasm汇编的转换场景，尤其适合那些需要以nasm代替gcc工具链进行编译、链接的场景。

## 用法

```
gas2nasm [-a][-e] input.s output.asm
```

编译选项，均来源于原来的gas2nask。说明如下：

-  -a：忽略`.text`中的`.balign 2`（减小无意义的对齐填充）
-  -e：内联展开`_lib_execcmd`函数（原作者专为OSASK设计的）

**（一般的使用场景下，这两个选项都可忽略。）**

输出的.asm文件支持被直接编译为COFF的对象文件或纯二进制.bin文件。建议编译命令：

```
nasm -f win32 file.asm -o file.obj
```

或

```
nasm -f bin file.asm -o file.bin
```



## 程序逻辑说明

核心处理逻辑是用convmain()两遍扫描输入。

第一遍作符号收集，在全文中查找所有形如`_xxx`的标签，若这些标签有形如`_xxx:`的定义或使用`.comm`与`.lcomm`定义，则标记为内部符号，否则标记为外部符号。扫描结束后，对于所有外部符号输出`EXTERN`伪指令。

第二遍作逐行翻译，对于`.`开头的行视为伪指令，按照对应的nasm形式转换输出，否则视为普通指令，在指令表中匹配对应的nasm指令，并将操作数从AT&T语法转为nasm语法并输出（对于`lock`/`rep`等前缀，识别后会递归地处理其之后的指令）。对于不支持的指令，打印`skip:`与原始行，同时置非零退出码，继续处理下一行。



## 在原程序上的改进

- 将输出改为nasm标准语法（主要是伪指令上的差异）。输出文件头时仍保留`[BITS 32]`，是为了部分用户需要将其编译成.bin的场景中，避免其被默认为16位文件；
- 完整支持`.text`/`.data`/`.bss`/`.rdata`四个段（在MinGW GCC的输出中，一般仅会有这四个段产生）；
- 支持`.comm`与`.lcomm`伪指令（常见于静态变量编译产物）；
- 支持`lock`、`rep`等指令前缀；
- 改造原指令表的结构（去除了8字符限制），新增了大量指令，几乎覆盖所有386/486用户态可能出现的指令及O2优化时极常见的CMOVcc指令。
- 修复了原程序的一些bug。



## 局限

以下默认处理行为基于MinGW-GCC的输出结果与符号约定，以及win32下nasm的处理约定，包括但不限于：

- 默认链接时的变量名、函数名以`_`开头，程序以此为约定做符号扫描并确定EXTERN与GLOBAL的对象；
- 只识别并处理`.text`/`.data`/`.bss`/`.rdata`四个段。如有后缀，会忽略并映射到对应的`[SECTION .text]`/`[SECTION .data]`/`[SECTION .bss]`/`[SECTION .rdata]`；
- 局部标签默认按照MinGW-GCC的形式，形如`L1`/`LC0`等。不考虑部分环境中，可能生成的以`.`开头标签的情况；
- `.ascii`指令的处理中，只考虑了GCC会输出的八进制转义字符，而忽略其它转义字符；
- 没有考虑寻址时段寄存器的存在（Linux有时栈保护的代码会使用到`%gs`）。



以下问题有待未来改进，包括但不限于：

- 几乎不支持SSE指令。可在将C程序编译为GAS汇编时，选择`-march=i486`或`-mno-sse`来规避；
- 对浮点指令的支持非常有限；

- 仅面向32位x86。[BITS 32]、寄存器集、指令表都按32位设计，不支持64位；
- 仅面向MinGW/WCOFF的输出结果与符号约定。其他环境下，GCC输出的文件可能无法被本工具正确转换。对于手工编写的AT&T格式`.s`汇编程序，也可能无法被本工具正确转换；
- 对`.space`伪指令的处理只是机械地翻译为`RESB`。虽然在非`.bss`段中，因这些数据需要实际写入文件，nasm约定使用`RESB`等价于用0填充，但会报出大量警告；
- 对`.align`等对齐指令的处理可能不正确或缺失，但多数情况下字节对齐不影响程序正常运行。



遇到无法转换的指令时，程序的默认行为是打印`skip:`并输出原始行，同时置非零退出码，继续处理下一行，生成的汇编文件中会缺失该行。有需要者，可以自行在`convmain`的表项中追加新的指令。

## 构建

因原作者均用Windows API进行文件读写操作，需在Windows环境下用MinGW构建：

```
gcc gas2nasm.c -o gas2nasm.exe
```

笔者比较偷懒，就没有将其用C标准库的`fopen`/`fread`/`fwrite`等进行改写，如有需要移植到其它编译环境的，可自行改写这些部分。
